# Чвстина №2
## 1. Чому аудіохарактеристики винесені в окремий об’єкт audio_features, а не зберігаються плоско? Коли таке вкладення вигідне, а коли створює проблеми?
З однієї сторони, виділення аудіохарактеристик у вкладений обʼєкт робить їх логічно згрупованими і при читанні документів, якщо вони частіше потрібні всі разом так легше їх додавати в проекцію, але, з іншої стророни, при пошуку по окремих характеристиках запити трохи подовжуються через те, що потрібно використовувати окремі поля цього вкладеного обʼєкту. На мою думку саме в цій задачі, для цих запитів, можно було зробити і пласку структуру
## 2. Чому виконавці зберігаються як масив, а не як рядок? Які запити стають простішими?
Тому що деякі треки мають більше одного виконавця. Це спрощує запити, наприклад знайти дует виконавців чи треки конкретного виконавці через селектори масива, а не текстового рядка, для якого довелося б писати пошук в середені рядка
